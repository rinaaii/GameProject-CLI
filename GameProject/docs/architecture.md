# Архітектура GameProject

Проєкт організовано за модульним принципом. Кожна частина має окрему відповідальність, а ключові залежності передаються через інтерфейси.

## Структура

- `Program.cs` — мінімальна точка входу.
- `CLI/` — інтерпретатор команд, парсер аргументів, реєстр команд і окремі набори команд для тексту та персонажів.
- `Abstractions/` — контракти `ICharacterStore` і `ITextWorkspace`. Команди працюють з контрактами, а не з конкретним способом зберігання.
- `Characters/` — модель персонажа, реалізації `Warrior` і `Mage`, здібності та реалізація сховища `CharacterStore`.
- `Items/` — абстракція предмета та конкретний `Item`.
- `TextModel/` — дерево вузлів документа та навігація/редагування робочого простору.
- `StructuredText/` — абстрактні елементи документа й builder API для програмного створення тексту.
- `Scenarios/` — сценарії ручного тестування двох режимів.

## Модульність і замінність

`CommandContext` отримує `ICharacterStore` та `ITextWorkspace`. Отже, команди не залежать від `CharacterStore` чи `TextWorkspace` напряму. Щоб використати файлове сховище, базу даних або іншу реалізацію дерева документа, достатньо реалізувати відповідний інтерфейс і замінити фабрику в `CLI/Application.cs`.

`Application` є composition root: тут створюються конкретні реалізації та передаються в контекст. `CommandRegistry` відокремлює маршрутизацію від виконання команд; нові команди можна додати реєстрацією без зміни парсера. `CharacterCommands` і `TextCommands` ізольовані один від одного, тому зміни однієї предметної області не потребують зміни іншої.

## Принципи проєктування

- **SRP:** парсер, реєстр, команди, модель персонажів і текстове дерево мають різні обов'язки.
- **OCP:** нові команди реєструються через `CommandRegistry`; альтернативні сховища реалізують інтерфейси.
- **LSP:** реалізації `ICharacterStore` та `ITextWorkspace` мають зберігати очікуваний контракт пошуку, додавання та навігації.
- **ISP:** інтерфейси описують тільки операції, потрібні командному шару для відповідної підсистеми.
- **DIP:** командний шар залежить від абстракцій, а конкретні реалізації підключаються на рівні запуску.

## Як перевірити вручну

1. Виконати `dotnet build` у каталозі `GameProject`.
2. Запустити `dotnet run -- --text` і повторити `Scenarios/text-mode.txt`.
3. Запустити `dotnet run -- --chars` і повторити `Scenarios/characters-mode.txt`.
